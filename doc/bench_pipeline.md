# Running the ClaMS benchmark pipeline

The benchmark entry point in this repository is
`script/benchmark/run_clams_bench.py`. There is no `run_clams_bench.sh` in this
checkout: the Python program **generates** a Slurm shell script named `job.sh`
and can optionally submit it. The generated job builds a k-nearest-neighbor
graph (kNNG), connects its components, builds an approximate minimum spanning
tree (AMST), runs ClaMS clustering, and optionally evaluates the labels.

## Prerequisites

- A configured and built ClaMS tree. From the repository root:

  ```bash
  cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build -j
  ```

- A Slurm cluster with `sbatch` for submission and `srun` on compute nodes.
  Generating `job.sh` does not require submitting a job.
- A point file readable by the kNNG builder.
- A work directory accessible to every participating node and process, with
  enough space for the intermediate datastores. Set `-w` to a shared
  filesystem path for a multi-node job. The output directory given by `-o`
  must also be accessible from the compute nodes for Slurm logs.
- Evaluation is skipped when `-g` is omitted. YGM evaluation (`-y`) requires installing the corresponding library; see [Evaluation](#evaluation).

Run the module from `build/` as in the examples below.

## Generate and submit a job

This example uses the MNIST files generated by
`dataset/mnist/download_mnist.py`. Use your own point and label files in the
same way.

```bash
cd build
python3 -m script.benchmark.run_clams_bench \
  -p ../dataset/mnist/points.txt \
  -g ../dataset/mnist/labels.txt \
  -w /tmp/clams-work \
  -o ./clams-results \
  -N 1 -T 16 \
  -B "-- --time=02:00:00 --account=BANK_ACCOUNT"
```

The command prints the job name, output and work directories, generated
`job.sh` path, and a ready-to-use `sbatch` command. It does **not** submit by
default. Run the printed `sbatch` command, or add `-S` to the generator command
to submit immediately. Replace the account, time limit, and shared paths with
values for your cluster.
The `-B` argument must be quoted and start with `--`
as shown so the command-line parser accepts the Slurm options.

To inspect all arguments and current defaults:

```bash
python3 -m script.benchmark.run_clams_bench -h
```

## Pipeline stages

The generated job runs these steps in order. Its `out.log` prints start and
finish timestamps for the main stages and the commands it executes.

| Stage | Action | Main intermediate result |
| --- | --- | --- |
| Build-kNNG (DNND) | Read points and build the kNNG with `build_knng`, or `build_knng_neo` with `--neodnnd`. | `dnnd_pm_datastore` |
| MFC | Compute bridge edges between graph components with `connect_mfc`. | No file is produced by the generated command |
| AMST | Build an approximate MST with `build_amst`, once per `-a` value. | `amst_pm_datastore_a<bound>` |
| ClaMS-HDBSCAN | Cluster each AMST for every `-m` value. | `cluster_labels_a<bound>_m<size>/` and `cluster_tree_a<bound>_m<size>/` |
| Optional noise-point clustering | Assign noise points to clusters when `--cluster_noise_points` is set. | `cluster_labels_a<bound>_m<size>_no_noise.txt` |
| Optional evaluation | Serialize labels and compare them with `-g`; if noise-point clustering is enabled, evaluate both label sets. | `cluster_labels_a<bound>_m<size>.txt` and metrics in `out.log` |

The intermediate paths in the last column are under the generated work
directory; `out.log` is under the output directory. `-a`
accepts one bound or a comma-separated list (for example, `-a 1.1,1.2`).
`-m` accepts one minimum cluster size, a comma-separated list, or an inclusive
integer range (for example, `-m 5,10,20` or `-m 5-10`). The job runs AMST once
for each bound, then clustering once for each minimum cluster size at that
bound. Defaults are `-a 1.1` and `-m 5`.

## Data exchange between programs

The programs communicate across stages through paths in the job's shared work
directory. Most stage inputs are **Metall persistent-memory (PM) datastores**:
directories containing binary files rather than line-oriented
text files.

| Producer → consumer | Path or location | Format and contents |
| --- | --- | --- |
| Point file → DNND | Input path passed with `-p` | Input in the format selected by `-f`; default `wsv` is whitespace-separated feature values, one point per row. Use `wsv-id` for rows beginning with an explicit point ID. |
| DNND → MFC and AMST | `dnnd_pm_datastore/` | Distributed Metall PM kNNG: point IDs and feature vectors, plus neighbor IDs and distances. DNND first builds a scratch datastore (by default at `/dev/shm/dnnd_datastore`) and copies it to this path. `-G` supplies an existing datastore instead. |
| AMST → clustering | `amst_pm_datastore_a<bound>/` | Distributed Metall PM list of weighted edges, each with two point IDs and a distance. There is one datastore per `-a` value. |
| Clustering → noise assignment and label serializer | `cluster_labels_a<bound>_m<size>/` | Metall PM datastore containing a `point_to_cluster_id_list` of `(point_id, cluster_id)` pairs. The generated command selects this format with the clustering executable's `-s` flag. `-1` denotes noise. |
| Clustering → inspection | `cluster_tree_a<bound>_m<size>/` | Cluster hierarchy data as per-rank `.csv` files. This directory is an output artifact, not an input to the next pipeline stage. |
| Label serializer → evaluator | `cluster_labels_a<bound>_m<size>.txt` | Plain text, one `point_id cluster_id` pair per line, separated by whitespace. The pairs need not be in point-ID order. Both the Python and YGM evaluators receive this file. |
| Optional noise assignment → evaluator | `cluster_labels_a<bound>_m<size>_no_noise.txt` | The same two-column text format, after noise points have been assigned. |

Except for the `-p` input, the paths in this table are relative to
`<work-root>/job_<timestamp>/`.

MFC opens the DNND datastore read-only and computes bridge edges. Its CLI can
write those edges as three-column text (`point_id point_id distance`) with
`-b`, and AMST can read that file with its own `-b`. The **generated benchmark
command supplies neither flag**, so it does not pass bridge edges from MFC to
AMST or modify the kNNG datastore. Inspect `job.sh` if you need to verify or
change this handoff for a particular run.

The serializer creates the original two-column text label file only when `-g`
requests evaluation. With `--cluster_noise_points`, the noise assignment
program reads both the AMST Metall datastore and the PM label datastore, then
writes the extra two-column text file whether or not `-g` is set. Ground-truth
labels are supplied separately through `-g`; their accepted text formats are
described in [Evaluation](#evaluation).

## Important options

| Options | Effect |
| --- | --- |
| `-p PATH` | Required point-data path. The file must be readable by the compute nodes. |
| `-f FORMAT`, `-d DISTANCE` | DNND input format and distance function; defaults: `wsv`, `l2`. |
| `-k K`, `--nng_r R`, `--nng_delta DELTA` | kNNG parameters; defaults: `50`, `0.5`, `0.0001`. |
| `--neodnnd` | Select `build_knng_neo`; `--neodnnd_threads` and `--neodnnd_replicate_rate` default to `2` and `0.0`. |
| `-G PATH` | Reuse an existing DNND PM datastore and skip the kNNG build. MFC and later stages still run. |
| `-R` | Back up the newly built kNNG datastore to `dnnd_pm_datastore_backup` after DNND. Has no effect when `-G` skips DNND. |
| `-a BOUNDS`, `-m SIZES` | AMST bounds and minimum cluster sizes to sweep. |
| `-g PATH` | Evaluate clustering against ground-truth labels. Omit it to skip evaluation. |
| `-y` | Use YGM evaluation instead of the Python evaluator; requires `-g` for evaluation to run. |
| `-z` | Give each noise point a singleton label in Python evaluation. |
| `--cluster_noise_points` | Produce and, with `-g`, evaluate a second label set after assigning noise points. |
| `-w DIR`, `-o DIR` | Roots for work files and job scripts/logs; each gets a unique `job_<timestamp>` subdirectory. Defaults: `/tmp` and `<current-directory>/bench_outputs`. The work subdirectory is created when the job runs. |
| `-N N`, `-T T` | Default nodes and MPI tasks per node for each stage; defaults: `1` and `32`. |
| `-S`, `-B "-- ..."` | Submit immediately; supply additional `sbatch` options. |
| `-v` | Request verbose output from stages that support it. |

Use `--dnnd-nodes`, `--mfc-nodes`, `--amst-nodes`,
`--clustering-nodes`, and `--ygm-eval-nodes` to override `-N` for individual
stages. Each has a corresponding `--<stage>-tasks-per-node` override for `-T`.
For example:

```bash
python3 -m script.benchmark.run_clams_bench \
  -p ../dataset/mnist/points.txt -w /shared/clams-work \
  -N 2 -T 16 --dnnd-nodes 4 --dnnd-tasks-per-node 32 \
  --clustering-nodes 1 --clustering-tasks-per-node 8
```

The batch allocation requests the maximum node count and maximum tasks per
node among its active MPI stages. Each `srun` then uses that stage's specified
size, with `--ntasks` equal to nodes times tasks per node. The optional `-R`
copy uses DNND's size. The YGM stage is active only when both `-g` and `-y`
are set. All size values must be positive integers.

## Evaluation

With `-g`, the default Python evaluator reads the serialized cluster labels
and ground truth. A simple label file has one label per line, corresponding
to point IDs `0, 1, ...` in order. The evaluator also accepts two columns,
`point_id label`, and ignores lines beginning with `#`. Its output, including
clustering quality metrics, appears in `out.log`.

To use distributed YGM evaluation, install corresponding binaries with
`python3 -m script.install_tpls`. YGM ground
truth must have two whitespace-separated columns on each line: `point_id label`.

```bash
python3 -m script.benchmark.run_clams_bench \
  -p ../dataset/mnist/points.txt \
  -g ../dataset/mnist/labels_with_point_ids.txt \
  -y -w /shared/clams-work \
  --ygm-eval-nodes 2 --ygm-eval-tasks-per-node 16
```

Use `-Y PATH` to select a different YGM executable. For other custom binary
locations, the generator also accepts `-D` (DNND), `-M` (MFC), `-A` (AMST),
`-C` (clustering), `--noise_point_clustering_exe`,
`--serialize_pm_cluster_data_exe`, and `--pm_datastore_copy_exe`. Use `-E`
to select another Python evaluator module or script.

## Find results and diagnose failures

Each generator run creates a `job_<timestamp>` directory under `-o`. The
generated job creates its matching work directory under `-w` when it runs:

```text
<output-root>/job_<timestamp>/
  job.sh       generated Slurm script
  info.txt     generator command and sbatch submission command
  out.log      Slurm standard output and stage/metric output, after submission
  err.log      Slurm standard error, after submission
<work-root>/job_<timestamp>/
  dnnd_pm_datastore
  amst_pm_datastore_a<bound>
  cluster_labels_a<bound>_m<size>/
  cluster_tree_a<bound>_m<size>/
  cluster_labels_a<bound>_m<size>.txt    if -g was used
```

Check `info.txt` for the exact submission command and `job.sh` for the exact
stage commands. On failure, read `err.log` and the last stage in `out.log`.
The generated script checks the return code of most stage commands and exits
on failure. If the job cannot find an input or executable, check paths relative
to the generator's working directory and their visibility on compute nodes.
If Slurm rejects the submission, check `-B` for your cluster's required account,
partition, and time limit. The generator itself does not verify a successful
`sbatch` submission, so confirm that Slurm accepted the job.

When using `-G`, the current generator writes an unquoted `Using existing DNND
datastore at ...` line into `job.sh`. The shell reports that line as `command
not found`, then continues because that line has no exit-status check. The
subsequent MFC and AMST commands still receive the `-G` path. Check the later
stage exit status to determine whether the reused datastore was read
successfully.
